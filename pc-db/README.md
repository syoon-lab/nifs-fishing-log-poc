조업기록(기존 이름: 바다기록) ZIP(schema 1~5)을 검증하여 로컬 SQLite에 보관하고, 작업별 근거를 검토한 뒤 PC 확인본을 확정하는 앱입니다. 조회·가져오기·검토 서버는 Python 표준 라이브러리로 실행합니다. PC 음성 처리는 워크스테이션에 있는 별도 GPU Python 환경과 로컬 모델을 사용합니다.

## 실행과 사용

Linux에서는 `./실행.sh`, macOS에서는 `실행.command`를 실행하거나 다음 명령을 사용합니다.

```sh
python3 app.py serve --port 8771
```

브라우저에서 <http://127.0.0.1:8771>을 엽니다. 실행기는 `python3 launch.py`입니다. 기존 2차 컨설팅 DB 뷰어(8770)와 별도 경로·포트·DB를 사용합니다. 기존 앱·휴대전화·보고서는 변경하지 않았습니다.

1. **자료 가져오기**: 기기·자료군 이름을 입력하고 휴대전화의 전체 내보내기 ZIP을 선택합니다. 같은 기기의 다음 ZIP에는 같은 이름을 사용합니다. 다른 이름으로 기존 식별자를 다시 등록하는 것은 거부합니다.
2. **가져오기 전 검증**: 모든 표·열·행·식별자·행 순서·연결 관계·JSON/CSV 값·원음 크기/해시·ZIP 파일 집합을 대조합니다. 표별 읽은 행·추가·동일·변경·누락·제외 수와 변경된 전후 값을 표시합니다. 원자료 입력은 아직 활성화하지 않습니다.
3. **판본 채택**: 후속 ZIP은 같은 기기의 현재 판본 이후 받은 전체자료임을 확인합니다. 기존 행 변경은 변경 내역 확인과 사유가 추가로 필요합니다. 파일명·파일 수정시각을 최신 판정 근거로 쓰지 않습니다. 내보낸 시각의 역전·형식 다운그레이드는 오류 확인을 위해 중단합니다.
4. **작업 검토**: 원음·전사 시도·휴대전화 수정본·어획 초안·질문/답변/보류/현장 확인 이력을 읽습니다. 한 조업의 추가 답변은 같은 작업 안에 표시합니다. 이전 조업 연결이 없는 녹음은 별도 LEGACY 작업으로 유지합니다.
5. **PC 확인본**: 필요한 후보 값을 항목별로 적용하거나 직접 입력합니다. 어획 목록 적용은 기존 입력이 있으면 교체를 확인합니다. 초안·과거 확인본·추가 녹음의 어획을 자동 합산하지 않습니다. 날짜 후보도 자동 확정하지 않습니다. 작업 내용·어법·목표 어종·이전 어구 수량/인원·투망일·양망/재투망 수량·처리·어획·특이사항·PC 메모를 저장합니다.
6. **확정/보류**: 검토자와 확인/수정 사유를 적고 검토 중 또는 확정을 선택합니다. 미확인 필수 항목은 보완하거나 ‘미확인 포함 확정’을 명시해야 합니다. 빈 값을 0으로 만들지 않습니다. 모의·실내 시험과 현장 실측을 자료 구분으로 표시합니다. 입력을 다시 저장하면 전후 판본이 누적됩니다.
7. **내보내기**: 현재 원자료와 일치하는 작업별 마지막 PC 확정본만 JSON/CSV로 내보냅니다. 검토 중으로 다시 저장한 작업과 새 근거로 재검토가 필요한 작업은 제외합니다. JSON에는 미확인 항목·검토자·사유·근거 판본 지문·이전 확인본 연결을 포함합니다. CSV의 행은 어획 항목별이며 작업 정보가 반복됩니다. 반복된 양망 수량 등을 행별 합산하면 안 됩니다. 정상 반복 어획 행은 임의로 제거하지 않습니다.

## 보존·판본 규칙

`data/records.sqlite3`는 `sources`(자료군별 현재 판본), `snapshots`(수신 순서·이전 판본·입력 지문·검증 보고), `raw_rows`(원본 표·식별자·순서·모든 값), `audio`(녹음별 원음 연결), `work_index`(작업별 근거 지문), `decisions`·`formal_catches`(PC 확인 이력)를 저장합니다.

- `data/archives/<sha>.zip`: 받은 ZIP을 바이트 단위로 그대로 보관합니다.
- `data/audio/<sha>.m4a`: 원음의 내용 지문으로 보관합니다. 서로 다른 정상 녹음의 내용이 같더라도 녹음 식별자·참조는 모두 유지합니다.
- `current_raw`는 자료군별 **현재 ZIP의 정확한 행 집합**입니다. 과거본과 합집합하거나 과거본으로 최신본을 자동 보충하지 않습니다.
- 이전 표·행이 하나라도 사라지면 현재 판본 갱신을 거부합니다. 사용자가 원인을 확인해야 하며, 자료 삭제나 축소 내보내기를 자동 승인하는 예외 기능은 제공하지 않습니다.
- 같은 식별자의 원음 변경, 다른 자료군과 겹치는 식별자, 알려지지 않은 표/열/형식, 고아 원음·관계 오류는 적재 전에 중단합니다.
- 원자료 판본·행·원음 명세·PC 확인본은 UPDATE/DELETE 방지 트리거로 보존합니다. 현재 판본 포인터만 트랜잭션 안에서 갱신합니다. 적재 실패 시 DB를 롤백하고 그 시도에서 새로 복사한 파일만 정리합니다.
- `current_formal`은 현재 근거와 일치하는 작업별 마지막 CONFIRMED만 선택합니다. `current_formal_catches`는 해당 확인본의 어획 행만 반환합니다. 자료 구분 TEST/FIELD/UNCLASSIFIED는 확인본 JSON의 `record_class`에 있습니다. 모든 확정본이 실제 현장 어획이라는 의미는 아닙니다.
- 원자료 변경으로 작업 근거 지문이 달라지면 이전 확정본은 이력에 보존하고 현재 확정 자료에서 제외합니다. 내보내기 시각만 바뀌고 작업 근거가 같다면 재확정을 요구하지 않습니다.
- 값이 같다는 이유로 다른 식별자의 정상 반복 기록을 제거하지 않습니다. 식별자는 문자열이며 앞자리 0을 유지합니다. CSV 수식 방지용 따옴표는 JSON 값에 반영하지 않습니다.

검토·확정은 로컬 앱의 업무 이력입니다. 입력한 검토자 이름은 인증/전자서명이 아니며, 기관 DB 서버와 연계하지 않습니다. PC 전사는 아래 별도 처리 이력에 저장하며 GPS 보간은 수행하지 않습니다.

## 재현·검증

```sh
python3 -m unittest discover -s . -p 'test_*.py' -v
python3 verify_initial_data.py
python3 app.py audit
python3 app.py preview /absolute/export.zip --source '윤석진 S24'
```

CLI 최초 적재는 `python3 app.py import ZIP --source 이름`, 후속 적재는 `--previous-sha 현재지문 --received-after`가 필요합니다. 기존 행 변경이 있으면 `--allow-changes --reason 사유`도 필요합니다. 먼저 preview의 전체 변경 내역을 확인하세요.

`recover_snapshot.py`는 schema 5의 유휴 ADB TAR을 **PC 재구성 ZIP**으로 만드는 도구입니다. 모든 DB 표·열을 조사하고 미확인 표나 비어 있지 않은 WAL/journal이 있으면 중단합니다. Android 로케일 메타데이터·모델·설정·별도 시험 DB는 조사 표로 합치지 않고 원본 TAR에 보존하며 파일별 처리 내역을 기록합니다. 원본 파일과 기존 산출물은 덮어쓰지 않습니다.

`verify_initial_data.py`는 가져오기 코드에 의존하지 않고 원본 TAR의 SQLite/원음 및 기존 PC SQLite/원음에서 직접 새 DB와 대조합니다. 초기 스냅샷 기준 검산용이므로 후속 자료를 실제로 수신한 뒤에는 해당 판본의 검산 범위를 별도로 지정해야 합니다.

검증 근거는 `검증자료/개발완료보고.md`, `원본직접_독립대조.json`, `S24_시험후_재구성검증.json`, `초기자료_가져오기검증.json`, `자동시험.log`에 있습니다. 변경 이력과 원본을 모두 보관하므로 디스크 사용량은 수신 판본에 따라 증가합니다. ZIP 1 GiB·압축 해제 2 GiB의 현재 한도를 넘으면 일부만 읽지 않고 중단합니다.


## PC 전사와 방언 모델 (2026-11-10)

화면 첫 부분에서 기록을 검색하고 자료군·사람 확인 상태·PC 처리 상태로 필터링합니다. 기록을 선택하면 원음, 휴대전화 전사와 확인본, 새 PC 전사와 추출 초안을 나란히 확인할 수 있습니다. 사람의 수정·확정은 **직접 검토·확정**을 펼쳐 진행합니다. 기존 ZIP 가져오기와 확정본 내보내기는 화면 아래에 있습니다.

**PC에서 다시 전사**는 선택한 작업의 모든 녹음을 개별 처리합니다. 기본 모델은 Whisper large-v3이며, 방언 선택 시 기본 전사를 보존하고 같은 원음을 해당 Whisper LoRA로 별도 전사합니다. 첫 연결에서는 A.X 4.0 Light로 항목을 추출했으며, 후속 개선부터는 이 컴퓨터에 설치되어 있던 Ollama `qwen3.6:35b`로 선택된 전사의 항목을 추출합니다. 방언 모델은 음성 인식용이고 Qwen은 항목 추출용입니다. 기본 전사 결과를 방언 처리 결과라고 표시하지 않습니다.

현재 `models.json`은 이 워크스테이션의 기존 `voicepeaceing-asr/.venv`·ASR 모델과 로컬 Ollama 모델 설정을 참조합니다. 외부 프로젝트의 코드·모델·환경을 수정하거나 새 모델을 다운로드하지 않았습니다. Whisper는 GPU 1을 사용합니다. 초기 A.X 구성은 GPU 0에서 추출했지만 현재 Qwen의 GPU 배분은 로컬 Ollama가 자동으로 정합니다. 경상·전라 모델은 화면에서 선택하며, 사용자가 선택한 경상 방언이 기본값입니다. 기기 간 동기화 후에는 이 설정의 경로를 확인하세요. Android SDK와 앱 서명 설정은 이번 PC 작업에서 변경하지 않았습니다.

- `data/processing.sqlite3`는 원자료 DB와 분리된 추가 전용 실행·상태 이력입니다. 원음 SHA-256, ASR 가중치·토크나이저·실행 코드·추출 지시문의 SHA-256, 추출 모델의 고정 digest, 패키지/API 버전, 입력 판본, 시각, 오류, 전사 원문과 추출 원문을 보존합니다.
- 같은 자료군·녹음 식별자·원음·모델 설정·입력 단계·소비한 질문 문맥의 성공/대기/실행 기록은 다시 추가하지 않습니다. 다른 녹음 식별자는 원음 바이트가 같아도 별도 기록입니다. 실패·중단은 원래 이력을 남기고 새 시도로 재처리합니다.
