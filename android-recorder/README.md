5. 확인 후 **빠진 내용 확인**에서 투망일 → 양망 수량 → 재투망/철거 → 필요한 재투망 수량 → 어획 항목을 하나씩 묻습니다. 자망은 “몇 폭”, 통발은 “몇 개”라고 묻습니다. **답변 녹음**으로 짧게 답하고 저장하면 같은 작업의 해당 항목을 보완합니다. “서른 개입니다”라는 양망 질문의 답을 재투망 수량이나 어획량으로 더하지 않습니다. **모름·나중에 확인**은 값 없이 미확인 이력으로 남기고 다음 질문으로 넘어갑니다. **기록 확인**을 다시 열면 보류한 질문도 확인할 수 있습니다. **직접 입력 · 확인**에서 투망일 후보를 적용하거나 직접 입력합니다. 자망은 폭, 통발은 개입니다. 양망 수량과 재투망 수량은 다르게 저장할 수 있습니다. 인식된 날짜를 조용히 확정하지 않으며 불명확하거나 서로 다른 투망일은 확인 대상으로 남깁니다. 어획량은 어종별로 보존합니다.
6. 투망일 음성 답변도 자동 확정하지 않으며 날짜 후보의 **맞음 · 적용**을 누르거나 직접 입력합니다. 질문·답변 원음·전사 원문·보류·확인 이력을 보존합니다. 불확실하거나 상충하는 답변은 확인 대상으로 유지합니다. 필요한 경우 **추가 녹음**으로 같은 작업을 보완합니다. 이를 별도 어획으로 더하지 않습니다. **기록 마침**에서 미확인 항목을 보완하거나 미확인으로 종료할 수 있습니다. 확인 중이면 기다리기/미확인 종료를 선택합니다. 입력을 모른다고 원음 저장을 막지 않습니다.
7. 다음 작업은 다시 **작업 기록 · 녹음**으로 시작합니다. 과거 항차나 투망 기록과 자동으로 연결하지 않습니다. 모든 작업을 마친 뒤 **입항**합니다.
8. **기록 보기**에서 원음·전사·현장 확인 이력을 봅니다. **전사 보기 → 항목 확인**의 새 자망·통발 편집 화면에서도 투망일·수량을 수정하고 확인본 일지에 저장할 수 있습니다. 현장 확인은 `FIELD_REVIEW` 이벤트로, 일지 확인본은 `transcript_reviews`·`structured_logs`·`gear_details`에 새 행으로 보존됩니다. 어느 쪽도 PC 정식 DB 최종 확정으로 취급하지 않습니다.
9. 입항 후 **더보기 → 자료 내보내기**로 모든 원자료·초안·확인 이력을 ZIP으로 저장합니다. 이전 자료와 새 자료를 함께 내보내며 휴대전화 자료는 삭제하지 않습니다.

화면이 꺼져 있어도 포그라운드 서비스로 기록을 계속합니다. 녹음 중 알림에는 **녹음 종료 · 저장**만 표시되며, 조업 종료·입항은 앱에서 순서대로 처리합니다. 중간에 그만둬야 할 때는 **더보기 → 기록 중단**으로 자료를 보존하고 항차·조업을 중단 상태로 남깁니다.

**작업 화면** 버튼이나 휴대전화 뒤로가기로 메인으로 돌아갑니다. 녹음 중에는 종료 버튼에 집중할 수 있도록 기록 보기 진입을 잠시 비활성화합니다.

위치 기록 간격(30초·1분·5분), 다음 녹음 제목, 위치 상태/설정, 모의 자료와 도움말은 **더보기**에 있습니다. 위치 간격은 항차 종료 후 변경할 수 있고, 실제 수신 주기는 보장되지 않습니다.

## 저장·복구 원칙

- 원음(M4A/AAC), 항차·조업·녹음 식별자, 측정 위치, 실제 측정 시각·수신 시각·정확도·위치 제공자와 이벤트를 기기 안에 보관합니다.
- 시작·종료 위치는 최근 60초 이내 실제로 수신한 위치를 참조합니다. 시작 시 없으면 녹음 시작 후 30초 이내 수신한 첫 위치를 연결할 수 있습니다. 실제 측정 시각은 별도로 보존하므로 녹음 시각과 같은 것으로 간주하면 안 됩니다.
- 위치를 못 얻었을 때는 좌표를 만들거나 0,0으로 채우지 않습니다. 시작·종료 위치가 없으면 `null`로 남습니다. 녹음 위치는 발화에서 언급한 조업 위치와 다를 수 있습니다.
- 위치 수집 간격은 운영체제에 요청하는 값입니다. GPS를 일정 주기로 완전히 끄고 켜는 절전 방식이 아니며, 실제 위치 간격과 배터리 소모는 실기기에서 확인해야 합니다.
- 앱 강제 종료·재부팅 후 자동으로 녹음하거나 위치 수집을 재개하지 않습니다. 재실행 시 기존 항차·진행 중인 조업·녹음에 `INTERRUPTED`를 표시하고 원파일을 보존합니다. 실제 종료 시각을 알 수 없으면 종료 시각을 추정하지 않습니다. 다시 시작하면 새 항차가 만들어집니다.
- 내보내기 중 녹음·위치 기록을 시작할 수 없습니다. 모든 저장된 항차가 ZIP에 포함되며, 실패·중단 기록도 제외하지 않습니다. 예상하지 못한 파일 누락·연결 없는 파일은 완료로 처리하지 않습니다.
- 내보내도 폰의 원자료는 지우지 않습니다. 앱 삭제·데이터 초기화 시 기기 내부 원자료가 삭제되므로 먼저 ZIP으로 내보내야 합니다. 기기 백업은 비활성화되어 있습니다.

기존 0.3.0 이하 자료는 원래 행·값·원음을 보존하여 이전합니다. 이전 녹음을 시작·특이사항·마무리로 추정하지 않으며 `LEGACY`(이전 자료 · 미분류)로 표시합니다.

## ZIP 구조 (schema_version 5)

| 파일 | 내용 |
|---|---|
| `audio/<recording-id>.m4a` | 원음. 실패·중단 녹음은 불완전할 수 있음 |
| `records.json` | 모든 원자료 행과 관계. 문자열 식별자·원문 보존 |
| `sessions.csv` | 항차 시작·종료 시각, 요청한 위치 간격, 상태, 작업순서 유형 |
| `operations.csv` | 항차 내 조업 회차, 시작·종료 시각, 상태·단계 |
| `recordings.csv` | 녹음 시각·제목·상태·파일 경로·시작/종료 위치 참조·조업 연결·녹음 종류(WORK/START/NOTE/END/LEGACY) |
| `locations.csv` | 모든 위치 측정값. 정상 반복 위치도 보존 |
| `events.csv` | 시작·종료·위치 제공자 변경·오류·중단 발견 이력, 질문과 답변 연결(FIELD_ANSWER_CONTEXT)·항목 보류(FIELD_QUESTION_DEFERRED) |
| `transcriptions.csv` | 전사 시도별 상태·원문·음성 구간·모델/원음 해시·실패 사유 |
| `transcript_reviews.csv` | 전사 원문을 보존한 사용자 확인/수정 이력 |
| `diary_entries.csv` | 확인본별 일지. 녹음 식별자·항차·조업·자동 시각과 확인 문장 |
| `structured_logs.csv` | 작업·목표 어종·어구 수량/단위·인원·어획 결과·특이사항의 추출 초안/확인본과 전체 근거 JSON |
| `catch_items.csv` | 어종별 수량·단위·kg 중량·근삿값 여부. 자동 초안과 확인 이력은 별도 행 |
| `gear_details.csv` | 자망·통발 추출본별 투망일·날짜 후보·확인 상태·양망 수량·재투망 수량·어구 단위·작업 후 처리·녹음일 |
| `manifest.json` | 파일별 바이트 수·SHA-256과 테이블별 행 수 |
| `읽어주세요.txt` | 시각·좌표·누락 상태 해석 |

시각은 UTC 기준 Unix 밀리초(`*_ms`), 좌표는 WGS84, `accuracy_m`은 미터입니다. `elapsed_ns`는 기기의 단조 시계로 재부팅 간 직접 비교할 수 없습니다. 화면의 시각은 휴대전화의 시간대로 표시합니다. CSV는 UTF-8 BOM이며 수식으로 해석될 수 있는 사용자 문자열 앞에 작은따옴표를 붙입니다. 정확한 문자열은 JSON에 보존됩니다.

## 현재 범위

원음 녹음 → 휴대전화 내부 전사 → 사용자 확인/수정 → SQLite 일지 저장까지 구현했습니다. whisper.cpp 1.8.7과 다국어 large-v3-turbo-q5_0 모델을 앱에 포함하고 CPU에서 실행합니다. 인터넷 권한·API 키·서버·Mac이 필요하지 않습니다. 메인 작업 화면은 기존 순차 버튼을 유지합니다.

이전 0.7.x 시작·마무리 흐름도 이력 열람·확인을 위해 유지합니다. 0.8.0의 새 작업은 WORK 단계 하나이며 시작·마무리 녹음을 요구하지 않습니다. 작업 인원은 새 WORK 자료에서 null이고 이전 값은 보존됩니다. 기존 0.7.0의 시작·마무리·보완 녹음은 저장 후 화면이 보일 때 한 건씩 자동 전사합니다. 잠금 화면에서 녹음을 종료한 경우 원음을 먼저 보존하고, 앱을 다시 열 때 미처리 항목 점검을 시작합니다. 진행 중 항차의 위치 기록은 계속됩니다. 전사 중 새 녹음은 확인 중지 후 시작하며 출항/내보내기를 제한합니다. 실패·중지된 작업을 자동으로 무한 재시도하지 않으며 **음성 다시 확인**으로 재시도할 수 있습니다. 알림과 화면에서 중지할 수 있고, 실패·중지 이력을 남겨 재시도합니다. 강제 종료 시 진행 중 전사는 INTERRUPTED로 복구하고 원음을 보존합니다. 전사 입력은 녹음 1건당 최대 30분이며 긴 파일을 조용히 잘라 처리하지 않습니다. 한 전사 작업은 최대 59분 실행 후 중단되며 Android 제한이 먼저 적용될 수 있습니다. 화면 잠금 중 CPU 처리를 위한 시간 제한 웨이크록을 사용합니다.

**어종·수량·중량 자동 추출을 지원합니다.** 업종 공통 어휘와 한글 수사(한·두·세·열두·쉰 등), 아라비아 숫자, 소수 중량, g→kg 변환을 처리합니다. 시작 녹음은 작업·목표 어종·어구 수량/단위·인원을, 마무리 녹음은 어종별 수량/단위·중량과 어획 결과를 추출합니다. 특이사항 녹음은 원문을 보존하고 선택 항목으로 취급합니다.

기존 small 모델의 ‘꽃게→꿋게’, ‘쉰 개→시인계’ 오류를 개선하기 위해 모델을 교체하고 업종 공통 어종·단위·숫자 어휘를 제공합니다. 특정 녹음의 정답 대본이나 실제 어획량을 전사 입력에 넣지 않습니다. ‘새 상자’처럼 숫자/일반 단어가 모호한 표기는 값으로 확정하지 않고 후보로 표시합니다. 원음 확인 후 후보를 적용하거나 직접 수정할 수 있습니다. 미등록 어종·범위·정정·서로 다른 수량은 확인 경고를 남깁니다. 모든 실제 발화의 무오류를 보장하는 기능은 아니며, 현장 소음·방언과 S24 장시간 성능 검증은 별도로 남습니다.

0.6.1에서는 어구 문맥의 “신계”를 **50개 후보 적용** 버튼으로 표시하여 수량과 단위를 함께 채웁니다. “쉰, 한, 개”처럼 쉼표로 나뉜 수사는 1개로 잘못 확정하지 않고 51개 후보로 남깁니다. 이미 확인한 값은 후보로 덮어쓰지 않습니다.

짧은 음성은 전체 길이를 포함하는 작은 처리 구간을 사용합니다. 마무리 발화에서 범위·정정·불확실한 수량과 미확인 어종이 함께 검출되면 기존 길이로 한 번 더 전사합니다. 이 경우 시간이 더 걸리며 두 시도의 원문을 모두 보존합니다. 전사 구간 시각은 실제 음성 길이 안으로 제한하고 조정 전 디코더 시각도 JSON에 남깁니다. 조정된 시각은 정밀 발화 정렬로 해석하지 않습니다.

모든 자동 항목은 DRAFT로 저장합니다. 사용자 확인본은 CONFIRMED이며 직접 수정한 항목의 전후 값도 기록합니다. 빈 값은 미확인이고 0으로 채우지 않습니다. 상자·개·마리는 kg으로 환산하지 않습니다. 목표 어종의 무어획과 전체 무어획, 미조업을 구분합니다. ‘무게 미측정’은 null, ‘어종 미확인 두 상자’는 어종 null/수량 2/단위 상자로 보존합니다. 전체 무어획과 양수 어획량이 동시에 있으면 충돌로 표시하며 모순된 상태로 확인 저장하지 못하게 합니다.

전사 구간 시각은 디코딩된 음성 시작점 기준 상대 밀리초이며 실제 조업 시각을 발화로 추정하지 않습니다. 원음·자동 원문·사용자 수정본은 별도로 보존하며 재전사도 새 시도로 남습니다. 일지 조회는 확인본을 녹음별 한 건으로 표시하지만 내보내기에는 모든 이력이 포함되므로 이력 행 수를 조업 건수로 집계하면 안 됩니다. 기존 DB 뷰어가 schema 3을 지원하는지는 별도 확인이 필요합니다.

## 현장 항목 점검과 보존 (0.7.0)

- 인식 실패를 실제 미발화로 단정하지 않습니다. 미확인 항목은 빈 값이며, 사용자가 확인 후 미확인 상태로 조업을 종료할 수 있습니다.
- 시작: 작업 내용·양의 정수 인원. 목표 어종은 선택, 어구 수량·단위는 말한 경우 점검합니다.
- 마무리: 어획 유무. 어획이 있으면 어종별 수량+단위 또는 kg 중량 중 하나 이상. 무어획·미조업은 구분하고 단위를 환산·수량 합산하지 않습니다.
- 여러 어종의 총 중량을 마지막 어종에 배분하지 않습니다. 이름을 모르는 어종과 단위 누락은 확인 대상으로 유지합니다.
- 보완 녹음은 원녹음을 대체하지 않는 NOTE 파일입니다. `FIELD_SUPPLEMENT` 이벤트가 원래 시작/마무리 단계와 조업을 연결합니다. 기존 시작/마무리 녹음 각각 한 건이라는 schema 4 규칙도 유지합니다.
- `FIELD_REVIEW` 이벤트 detail(JSON version 1)에 현장 확인값·이전 값·근거 녹음/전사/확인본 식별자와 `FIELD_ONLY_NOT_PC_FINAL`을 기록합니다. 원음·전사 원문·structured_logs의 기존 확인본을 덮어쓰지 않습니다. 기존 ‘일지 보기’와 현장 확인은 별도 화면입니다.
- `FIELD_CHECK_REQUESTED`, `FIELD_ASR_ATTEMPTED`, `FIELD_NOTICE_SHOWN`, `FIELD_DEFERRED`, `FIELD_OPERATION_CLOSE`에 점검 요청·시도·안내·보류·종료 시 미해결 항목을 남깁니다. ZIP의 events.csv/records.json에 모두 포함합니다.
- 같은 결과의 안내 팝업은 반복하지 않습니다. **기록 확인**, **기록 보기 → 현장 확인**에서 다시 열 수 있습니다. 다음 조업은 별도 식별자로 점검합니다.
- 자동 전사 시작은 보이는 Activity에서 수행합니다. [Android 백그라운드 FGS 시작 제한](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), [mediaProcessing 유형](https://developer.android.com/develop/background-work/services/fgs/service-types#media-processing)을 따릅니다. 재부팅·프로세스 종료 후 녹음/항차를 자동 재개하지 않습니다.

## 내보낸 파일 독립 확인

PC에서 추가 패키지 없이 파일 수·테이블 행 수·CSV/JSON 값·연결 식별자·원음 SHA-256를 대조할 수 있습니다. 이 검증으로 음성의 청취 품질이나 실제 위치의 정확성이 확인되는 것은 아닙니다.

```sh
python3 tools/verify_export.py 내보낸파일.zip
```

원자료 사본과 실제 ZIP 전체 대조(ADB로 확보한 유휴 상태의 `databases`, `files` TAR 필요):

```sh
python3 tools/reconcile_device_export.py 원자료.tar 내보낸파일.zip 검산결과.json
```

검증기는 기존 schema 1·2·3·4를 구분하여 모든 표·열·행·식별자 연결·원음 파일을 확인합니다. 이전 자료를 새 조업으로 합치지 않습니다.

`개발의존성/whisper.cpp`는 v1.8.7, commit `48f628a84833905ee4a0658ee6d4a5c915ce1997`의 원본 checkout입니다. 앱 모델은 [공식 변환 모델 저장소](https://huggingface.co/ggerganov/whisper.cpp) revision `5359861c739e955e79d9a303bcbc70fb988958b1`의 `ggml-large-v3-turbo-q5_0.bin`입니다. SHA-256 `394221709cd5ad1f40c46e6031ca61bce88931e6e088c188294c6d5a55ffa7e2`, 574,041,195 bytes. 이전 small 모델과 0.5.0 APK는 보존했습니다.

## 구조화 자료 집계

`structured_logs.status=CONFIRMED`인 행 가운데 녹음별 가장 최근 확인본만 선택합니다. 연결된 `catch_items`에서 마리·상자·개 등 단위를 구분하고, 중량은 `weight_kg`로 읽습니다. null을 0으로 치환하지 않습니다. 자동 DRAFT, 재전사, 과거 확인본을 합산하면 중복됩니다. `data_json`에는 원문 근거, 추출 경고, 동음 숫자 후보, 사용자 변경 내역이 있으며 후보값은 수량 열에 반영되지 않습니다. `transcription_id → recordings.operation_id`로 시작/마무리/특이사항을 같은 조업 회차에 연결할 수 있습니다.
